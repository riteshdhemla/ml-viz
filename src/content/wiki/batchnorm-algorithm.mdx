# Batch Normalization: Forward Pass & Running Stats

Batch Normalization (Ioffe & Szegedy, 2015) normalizes the pre-activations of each layer across the current mini-batch, then re-scales with learnable parameters. This stabilizes the optimization landscape, enables higher learning rates, and reduces sensitivity to weight initialization.

## The three-step forward pass

For a mini-batch of $m$ pre-activations $x_1, \ldots, x_m$ at one feature:

**Step 1 — mini-batch statistics:**

$$
\mu_B = \frac{1}{m}\sum_{i=1}^m x_i, \qquad \sigma_B^2 = \frac{1}{m}\sum_{i=1}^m (x_i - \mu_B)^2
$$

**Step 2 — normalize:**

$$
\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}
$$

where $\epsilon \approx 10^{-5}$ prevents division by zero. After this step: $\mathbb{E}[\hat{x}] = 0$, $\text{Var}[\hat{x}] = 1$.

**Step 3 — rescale with learnable $\gamma$ and $\beta$:**

$$
y_i = \gamma \hat{x}_i + \beta
$$

After rescaling: $\mathbb{E}[y] = \beta$, $\text{Var}[y] = \gamma^2$.

**Why two steps?** Normalizing alone forces mean 0 and variance 1, which might not be optimal for the downstream layer. The learnable $\gamma$ and $\beta$ restore full expressivity — at the limit they can undo the normalization entirely, but the smooth optimization landscape encourages useful, near-identity values.

## Worked example: $\mathbf{x} = (2, 4, 6, 8)$, $m = 4$

**Step 1 — statistics:**

$$
\mu_B = \frac{2+4+6+8}{4} = 5, \qquad \sigma_B^2 = \frac{(-3)^2+(-1)^2+1^2+3^2}{4} = \frac{9+1+1+9}{4} = 5
$$

**Step 2 — normalize** ($\epsilon = 0$ for clarity):

$$
\hat{\mathbf{x}} = \left(\frac{2-5}{\sqrt{5}},\ \frac{4-5}{\sqrt{5}},\ \frac{6-5}{\sqrt{5}},\ \frac{8-5}{\sqrt{5}}\right) \approx (-1.342,\ -0.447,\ 0.447,\ 1.342)
$$

Verify: mean $= 0$ ✓, variance $= \frac{1.342^2+0.447^2+0.447^2+1.342^2}{4} = 1$ ✓

**Step 3 — rescale** with $\gamma = 2$, $\beta = 1$:

$$
\mathbf{y} = 2\,\hat{\mathbf{x}} + 1 \approx (-1.683,\ 0.106,\ 1.894,\ 3.683)
$$

Verify: mean $= (−1.683+0.106+1.894+3.683)/4 = 1 = \beta$ ✓, variance $= 4 = \gamma^2$ ✓

## Running statistics for inference

During training, batch statistics are computed fresh each mini-batch. At inference time (often a single sample with no batch), BatchNorm switches to **running averages** accumulated during training via an exponential moving average:

$$
\mu_{\text{run}} \leftarrow (1 - \alpha)\,\mu_{\text{run}} + \alpha\,\mu_B
$$

$$
\sigma^2_{\text{run}} \leftarrow (1 - \alpha)\,\sigma^2_{\text{run}} + \alpha\,\sigma_B^2
$$

where $\alpha \approx 0.1$ is the momentum parameter. At inference, the layer uses the fixed $\mu_{\text{run}}$, $\sigma^2_{\text{run}}$ instead of batch statistics, making predictions fully deterministic.

<Callout type="warning" title="Train vs. eval mode">
  In PyTorch, always call `model.eval()` before inference. In train mode, BatchNorm uses stochastic batch statistics. In eval mode, it uses the deterministic running statistics. Forgetting this causes unpredictable inference errors, especially on single-sample inputs where batch variance is undefined.
</Callout>

## NumPy from-scratch implementation

```python
import numpy as np

def batchnorm_forward(x, gamma, beta, eps=1e-5):
    """
    x:     (N, D) — N samples, D features
    gamma: (D,)   — per-feature scale
    beta:  (D,)   — per-feature shift
    Returns: y (N,D), cache for backward pass
    """
    mu    = x.mean(axis=0)              # (D,)
    var   = x.var(axis=0)               # (D,)
    x_hat = (x - mu) / np.sqrt(var + eps)
    y     = gamma * x_hat + beta
    return y, (x, x_hat, mu, var, gamma, eps)

# Reproduce the worked example (1 feature, 4 samples)
x = np.array([[2.0], [4.0], [6.0], [8.0]])  # (4, 1)
gamma, beta = np.array([2.0]), np.array([1.0])

y, _ = batchnorm_forward(x, gamma, beta, eps=0)
print("x_hat:", ((x - x.mean()) / x.std()).ravel().round(3))
print("y:    ", y.ravel().round(3))   # [-1.683  0.106  1.894  3.683]
print(f"mean(y)={y.mean():.3f}  var(y)={y.var():.3f}")  # 1.000, 4.000

# Simulate running statistics accumulation over 5 training batches
mu_run, var_run = 0.0, 1.0
alpha = 0.1
for mu_b, var_b in [(5.0, 5.0), (4.8, 4.9), (5.2, 5.1), (5.0, 4.8), (4.9, 5.0)]:
    mu_run  = (1 - alpha) * mu_run  + alpha * mu_b
    var_run = (1 - alpha) * var_run + alpha * var_b

print(f"\nRunning mean after 5 batches: {mu_run:.4f}")  # converges toward 5
print(f"Running var  after 5 batches: {var_run:.4f}")  # converges toward 5
```

## Where BatchNorm is placed

The original paper normalizes **pre-activations** (before the nonlinearity): `Linear → BN → ReLU`. In practice "BN after activation" sometimes works better for residual networks. Transformers use **LayerNorm** instead — normalized over the feature dimension rather than the batch dimension — which works well at batch size 1.
