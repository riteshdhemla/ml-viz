# Variable Elimination

**Variable elimination** is the workhorse algorithm for *exact* inference in [Bayesian Networks](/courses/graphical-models/01-bayesian-networks). Given a query like $P(\text{Disease} \mid \text{Symptoms})$, it computes the answer by summing out every non-query variable, but does so factor by factor, in a chosen order, instead of building the full joint table.

## Why not sum the full joint distribution

The naive approach (build the full joint $P(X_1, \ldots, X_n)$ and marginalize) costs $O(2^n)$ for $n$ binary variables. Variable elimination exploits the network's factorization to keep intermediate tables small: it interleaves multiplication and summation so no factor ever has to mention more variables than necessary.

## The variable elimination procedure

To compute $P(Q \mid E = e)$ (query $Q$, evidence $E$):

1. **Set evidence:** for each observed variable $E_i = e_i$, replace its CPT with a factor restricted to $E_i = e_i$.
2. **Choose an elimination ordering** $Z_1, Z_2, \ldots, Z_k$ over the hidden variables (all except $Q$). Good orderings keep intermediate factors small.
3. **For each $Z_i$ in order:**
   a. Collect all factors that mention $Z_i$.
   b. Multiply them into one big factor: $f_\text{new}(\ldots) = \prod_j f_j(\ldots)$.
   c. Sum out $Z_i$: $g(\ldots) = \sum_{z_i} f_\text{new}(\ldots, Z_i = z_i)$. Replace the original factors with $g$.
4. **Multiply remaining factors** and normalize to get $P(Q \mid E = e)$.

## A worked example

Network: Rain → Sprinkler, Rain → Wet, Sprinkler → Wet. Query: $P(\text{Wet} \mid \text{Rain=T})$.

**Step 1 — set evidence.** Restrict every factor that mentions Rain to Rain = T:
- $P(\text{Rain})$ → constant $P(\text{Rain=T}) = 0.2$
- $P(\text{Sprinkler} \mid \text{Rain})$ → $P(\text{Sprinkler} \mid \text{Rain=T})$, a factor over Sprinkler only
- $P(\text{Wet} \mid \text{Sprinkler}, \text{Rain})$ → $P(\text{Wet} \mid \text{Sprinkler}, \text{Rain=T})$, a factor over (Wet, Sprinkler)

**Step 2 — ordering.** Only one hidden variable: Sprinkler.

**Step 3 — eliminate Sprinkler.** Using CPT values: $P(S=T \mid R=T) = 0.01$, $P(W=T \mid S=T, R=T) = 0.99$, $P(W=T \mid S=F, R=T) = 0.80$. Multiply the two factors that mention Sprinkler, then sum over its two values:

$$
g(\text{Wet=T}) = \sum_{s \in \{T, F\}} P(s \mid R=T)\; P(W=T \mid s, R=T)
$$

$$
= 0.01 \times 0.99 + 0.99 \times 0.80 = 0.0099 + 0.7920 = 0.8019
$$

**Step 4 — normalize.** Compute $g(\text{Wet=F}) = 0.01 \times 0.01 + 0.99 \times 0.20 = 0.1981$. These sum to $1.000$, so no further normalization is needed: $P(\text{Wet=T} \mid \text{Rain=T}) \approx 0.802$. Even with the sprinkler being off 99% of the time when it rains, the rain itself makes the grass likely wet.

## Watch it run

The example above has only one hidden variable, so there is no ordering to get
wrong. Add a Slippery node (Wet → Slippery) and query $P(\text{Slippery})$ with
nothing observed, and all three of Rain, Sprinkler and Wet must be summed out —
now the order matters. The CPTs are the canonical sprinkler numbers, extended
with $P(S{=}T \mid R{=}F) = 0.4$, $P(W{=}T \mid S{=}T, R{=}F) = 0.9$,

What to notice as you step:

- **Only the factors mentioning the eliminated variable take part.** Everything
  else is left alone. That locality is the whole saving over building the joint.
- **Watch the row counts, not the probabilities.** The cost of the algorithm is
  the size of the largest intermediate factor, and you can see it swell on the
  multiply and shrink on the sum-out.
- **The last step re-runs the same query in a worse order.** The answer is
  identical to the last digit — variable elimination is exact under any
  ordering, but the largest table doubles. On four binary variables that is a
  shrug; the same effect on a real network is the difference between seconds and
  never finishing, which is what the next section is about.

## Complexity and the elimination order

The cost is exponential in the size of the *largest intermediate factor*, which depends on the elimination order. The best achievable maximum factor size (minus one) is the graph's **treewidth**, so variable elimination is tractable for tree-like networks and expensive for densely connected ones.

<Callout type="tip" title="Choosing an order">
  Finding the optimal elimination order is NP-hard, but greedy heuristics work well in practice: at each step, eliminate the variable that creates the smallest new factor (min-fill or min-degree heuristics).
</Callout>

For graphs where exact inference is intractable, switch to approximate methods — sampling (likelihood weighting, Gibbs/MCMC) or loopy belief propagation.
