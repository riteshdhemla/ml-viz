# BatchNorm & Dropout

Two techniques transformed deep learning from an art into an engineering discipline: **Batch Normalization** and **Dropout**. Neither is about the network's hypothesis class — they do not change what functions the network can represent. Instead, they change the *optimization landscape*, making it easier to find good solutions and harder to memorize noise.

## The problem: internal covariate shift

Each layer of a deep network receives inputs whose distribution shifts every time the weights of the previous layer change. This **internal covariate shift** slows training because later layers must constantly adapt to a moving target.

Concretely, imagine training a five-layer network. After one gradient step, the first layer's weights change slightly, which changes the distribution of activations entering the second layer, which changes what the second layer needs to do, which changes the gradients the third layer sees — a cascade that makes each layer's job harder than it needs to be.

**Symptoms in practice:**
- Saturating activations (sigmoid/tanh outputs stuck near ±1, gradient ≈ 0)
- Need for very careful weight initialization
- Need for very small learning rates
- Training instability that worsens with depth

## Batch Normalization

**Batch Normalization** (Ioffe & Szegedy, 2015) normalizes the pre-activations of each layer across the current mini-batch, then re-scales with learnable parameters:

$$
\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}, \qquad y_i = \gamma \hat{x}_i + \beta
$$

where $\mu_B = \frac{1}{m}\sum_{i=1}^m x_i$ and $\sigma_B^2 = \frac{1}{m}\sum_{i=1}^m (x_i - \mu_B)^2$ are the mini-batch mean and variance, and $\gamma, \beta$ are learned per-feature scale and shift.

**Why two steps?** The normalization step forces zero mean and unit variance. But sometimes the network needs a non-zero mean or non-unit variance for its activations — the learned $\gamma, \beta$ restore that flexibility. At the limit, if $\gamma = \sigma_B$ and $\beta = \mu_B$, the layer has learned to undo the normalization entirely — but in practice this never happens because the smooth optimization landscape encourages smaller, useful values.

**Inference mode:** During training, BatchNorm uses mini-batch statistics, which vary each step. At inference time, the batch may contain just one sample, making batch statistics meaningless. Instead, BatchNorm accumulates **running statistics** during training: $\mu_\text{run} \leftarrow 0.9\,\mu_\text{run} + 0.1\,\mu_B$ (exponential moving average). At inference, these fixed running statistics replace $\mu_B$ and $\sigma^2_B$, making predictions deterministic. This is why calling `model.eval()` is essential — it switches the mode.

<Callout type="warning" title="Train vs. eval mode">
  Forgetting to call `model.eval()` in PyTorch before inference is a common bug. In train mode, BatchNorm uses batch statistics (stochastic). In eval mode, it uses running statistics (deterministic). Failing to switch causes random-looking inference errors, especially on single-sample inputs.
</Callout>

### What BatchNorm buys you

- **Higher learning rates** — the normalized landscape has more consistent curvature
- **Less sensitivity to initialization** — bad initial weights are corrected at the first forward pass
- **Mild regularization** — batch statistics add noise (each example is normalized relative to other random examples in the batch)
- **Faster convergence** — often 5-10× fewer iterations to the same accuracy

```python
import numpy as np

def batchnorm_forward(x, gamma, beta, eps=1e-5):
    """BatchNorm forward pass. x: (N, D) mini-batch."""
    mu  = x.mean(axis=0)
    var = x.var(axis=0)
    x_hat = (x - mu) / np.sqrt(var + eps)
    return gamma * x_hat + beta
```

## Dropout

**Dropout** (Srivastava et al., 2014) randomly zeroes a fraction $p$ of a layer's activations during each training forward pass — each neuron is independently retained with probability $(1-p)$ and dropped (set to zero) with probability $p$.

$$
r_i \sim \text{Bernoulli}(1-p), \qquad \tilde{h}_i = r_i \cdot h_i / (1-p)
$$

The division by $(1-p)$ is **inverted dropout** — it keeps the expected activation magnitude the same, so no scaling is needed at test time. At inference, dropout is disabled and all neurons are used (with the original weights, unscaled).

### The ensemble interpretation

Dropout is equivalent to training an **ensemble of** $2^N$ **different networks** (where $N$ is the number of dropped neurons) with shared weights. Each forward pass samples a different "thinned network" from this exponentially large ensemble.

**Why does test-time averaging approximate the ensemble mean?** Consider one neuron with weight $w$ and input $x$. During training with dropout rate $p$, inverted dropout scales active neurons by $1/(1-p)$:
- With probability $(1-p)$: contribution = $\frac{w}{1-p} \cdot x$
- With probability $p$: dropped, contribution = $0$

Expected contribution = $(1-p) \cdot \frac{wx}{1-p} = wx$.

At test time all neurons are active and unchanged (no scaling needed) — each contributes $wx$. The test-time output therefore equals the expected training-time output, which is the expectation over all $2^N$ ensemble members.

Ensembles reduce variance — different ensemble members make different errors, and averaging them out reduces overfitting. Dropout achieves this benefit implicitly, at nearly zero additional cost.

### The regularization interpretation

Neurons with dropout cannot rely on any specific other neuron always being present. This forces the network to learn **redundant representations** — multiple neurons must each independently encode useful features. This is mathematically similar to L1 and L2 regularization:

| Method | Mechanism | Effect |
|--------|-----------|--------|
| L2 regularization | Penalizes large weights | Shrinks all weights toward zero |
| L1 regularization | Penalizes weight magnitude | Sparsifies weights |
| Dropout | Randomly zeros activations | Forces redundant, independent features |

In fact, for a linear model, dropout with rate $p$ applied to inputs is equivalent to L2 regularization with penalty proportional to $p/(1-p)$.

<Callout type="info" title="Typical dropout rates">
  A dropout rate of $p = 0.5$ (drop 50% of neurons) is standard for fully-connected layers. For convolutional layers, $p = 0.1$–$0.2$ is more common — spatial features are spatially correlated, so dropping entire feature maps (SpatialDropout) is more effective than dropping individual pixels.
</Callout>

### Worked example: one forward pass

Hidden layer activations: $\mathbf{h} = (2.0,\ 1.5,\ 3.0,\ 0.5)$. Dropout rate $p = 0.5$.

**Step 1 — sample mask** $\mathbf{r} \sim \text{Bernoulli}(0.5)^4$. Say we get $\mathbf{r} = (1, 0, 1, 0)$ (neurons 0 and 2 survive).

**Step 2 — apply and scale:** $\tilde{\mathbf{h}} = \mathbf{r} \odot \mathbf{h} / (1-p) = (4.0,\ 0,\ 6.0,\ 0)$.

The scale factor $1/(1-p) = 2$ compensates for the halved expected sum, so the downstream layer sees the same expected magnitude regardless of $p$.

```python
def dropout(h, p, training=True, seed=None):
    """Apply inverted dropout. p: drop probability."""
    if not training:
        return h                          # inference: no dropout
    rng = np.random.RandomState(seed)
    mask = (rng.rand(*h.shape) > p).astype(float)
    return h * mask / (1.0 - p)
```

## BatchNorm vs. Dropout: when to use which

| | BatchNorm | Dropout |
|--|-----------|---------|
| **Primary effect** | Stabilizes optimization | Reduces overfitting |
| **Used in** | CNNs, dense layers | Dense layers, transformers |
| **Combined with** | Usually comes before activation | Usually comes after activation |
| **Not effective for** | Very small batches (< 4) | Convolutional feature maps (use SpatialDropout) |
| **Modern substitute** | LayerNorm (Transformers) | Weight decay / data augmentation |

For CNNs specifically — where batch size is often small (large images, detection/segmentation) but LayerNorm's "pool everything" reduction is too coarse — **GroupNorm** and **InstanceNorm** offer a middle ground, each normalizing per-sample so neither needs running statistics at all:

## Common mistakes

1. **Leaving dropout on at test time** — dropout should be disabled during inference (`model.eval()` in PyTorch). Leaving it on gives stochastic predictions and typically worse accuracy.
2. **Applying BatchNorm with batch size 1** — with a single example, batch variance is undefined. Use GroupNorm or InstanceNorm for single-sample inference or very small batches.
3. **Using dropout in place of BatchNorm for instability** — they address different problems. If training is unstable (exploding/vanishing gradients), add BatchNorm. If training accuracy is much higher than validation accuracy (overfitting), add dropout.

## Key takeaways

- **BatchNorm** normalizes pre-activations per mini-batch, then re-scales with learnable $\gamma, \beta$; it speeds convergence and reduces sensitivity to initialization.
- At **inference**, BatchNorm uses running statistics (computed during training) — always call `model.eval()`.
- **Dropout** randomly zeroes activations during training; at test time all neurons are active (no scaling needed with inverted dropout).
- Dropout ≈ **implicit ensemble** of $2^N$ networks; also similar to L2 regularization on the feature representation.
