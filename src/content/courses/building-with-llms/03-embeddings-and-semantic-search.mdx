# Embeddings & Semantic Search

Keyword search matches *strings*. Semantic search matches *meaning*: "How do I get my money back?" should find a document titled "Refund policy" even though they share no words. The enabling idea is the **embedding** — a vector representation of text where distance encodes semantic similarity. This lesson builds the retrieval engine that the next lesson (RAG) plugs an LLM into.

**Real-world examples:** document and code search, deduplication, recommendation, clustering, and the retrieval half of every RAG system.

## From text to vectors

An **embedding model** maps a piece of text to a dense vector $\mathbf{e} \in \mathbb{R}^d$ (typical $d$ = 384–3072). Trained well, it places paraphrases close together and unrelated text far apart. Modern sentence/document embedders are themselves transformer encoders fine-tuned with a **contrastive objective** — pull matching pairs together, push mismatched pairs apart.

<Callout type="info" title="Not the same as token embeddings">
  The token embeddings inside a transformer represent single tokens. A *sentence/document* embedding represents an entire passage as one vector — usually by pooling the model's contextual token outputs. Same idea (vectors that encode meaning), different granularity.
</Callout>

## Measuring similarity

Once text is a vector, similarity is geometry. The workhorse is **cosine similarity** — the cosine of the angle between two vectors, ignoring their magnitude:

$$
\text{cos}(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{\lVert \mathbf{a}\rVert\, \lVert \mathbf{b}\rVert}
$$

It ranges from $-1$ (opposite) through $0$ (unrelated) to $1$ (identical direction). Cosine is preferred over raw Euclidean distance because it focuses on *direction* (topic) rather than *length* (which often just tracks text length).

<Callout type="tip" title="Normalized embeddings: cosine = dot product">
  Modern embedding models (OpenAI, Sentence-BERT) output **L2-normalized (unit-norm)** vectors: $\|\mathbf{a}\| = \|\mathbf{b}\| = 1$. For unit vectors the denominator is $1 \times 1 = 1$, so $\text{cos}(\mathbf{a}, \mathbf{b}) = \mathbf{a} \cdot \mathbf{b}$ exactly. This is why vector databases default to **inner-product (dot-product) indexes** — it's the same as cosine but cheaper. If you're unsure whether your embeddings are normalized, normalize first with `a / np.linalg.norm(a)`.
</Callout>

```python
import numpy as np

def cosine(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

query = embed("how do I get my money back?")
docs  = [embed(d) for d in corpus]
ranked = sorted(corpus, key=lambda d: cosine(query, embed(d)), reverse=True)
```

## Semantic vs keyword search

| | Keyword (BM25 / TF-IDF) | Semantic (embeddings) |
|---|---|---|
| Matches | exact terms | meaning / paraphrase |
| "money back" → "refund" | ✗ | ✓ |
| Rare exact IDs / codes | ✓ | sometimes ✗ |
| Needs a model | no | yes (embedder) |

Neither dominates everywhere — production systems often run **hybrid search** (combine both scores) to get exact-match precision *and* semantic recall.

## Scaling: the vector index

Comparing a query against millions of vectors one-by-one (exact nearest-neighbour) is too slow. **Vector databases** use **Approximate Nearest Neighbour (ANN)** indexes (e.g. HNSW graphs, IVF) that trade a little recall for orders-of-magnitude speed.

<Callout type="warning" title="The ANN trade-off">
  ANN returns *most* of the true neighbours, *most* of the time. You tune a knob (graph degree, number of probes) that trades **recall vs latency**. For RAG this is usually fine — but be aware your retriever is approximate.
</Callout>

## Common mistakes

1. **Mixing embedding models** — a query embedded by model A can't be compared to documents embedded by model B.
2. **Forgetting to normalise** when your similarity assumes unit vectors.
3. **Assuming ANN is exact** — it isn't; validate recall on a sample.
4. **Using semantic search for exact-ID lookups** — keyword/hybrid is better there.

## Key takeaways

- An **embedding** turns text into a vector whose geometry encodes meaning.
- **Cosine similarity** ranks documents by semantic closeness to a query, matching paraphrases with no shared words.
- **Hybrid search** combines keyword precision with semantic recall.
- **ANN vector indexes** make search over millions of vectors fast, at the cost of approximate recall.
