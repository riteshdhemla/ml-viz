# Boosting

Bagging trains trees independently and averages them. **Boosting** trains trees **sequentially**, where each tree corrects the mistakes of the previous one. This reduces **bias** (underfitting), not just variance.

**Real-world examples:** Search ranking, click-through prediction, Kaggle competitions (XGBoost dominates tabular data).

## The boosting idea

1. Start with a simple model (e.g., a shallow tree)
2. Find the examples it gets wrong
3. Train a new model focusing on those mistakes
4. Combine all models weighted by their accuracy
5. Repeat until $B$ models are trained

$$
\hat{f}_B(\mathbf{x}) = \sum_{b=1}^{B} \eta \cdot h_b(\mathbf{x})
$$

where $h_b$ is the $b$-th weak learner and $\eta$ is the **learning rate** (shrinkage).

<Callout type="tip" title="Analogy">
  Imagine a student taking practice exams. After each exam, they focus on the questions they got wrong. Over time, they improve not by studying everything equally, but by targeting their weaknesses. Boosting does this with models.
</Callout>

## AdaBoost (1995)

The original boosting algorithm:

1. Initialize equal weights $w_i = 1/n$ for all samples
2. Train weak learner $h_b$
3. Compute weighted error: $\epsilon_b = \frac{\sum_{i: h_b(\mathbf{x}_i) \neq y_i} w_i}{\sum w_i}$
4. Compute model weight: $\alpha_b = \frac{1}{2} \ln\left(\frac{1 - \epsilon_b}{\epsilon_b}\right)$
5. Update sample weights: $w_i \leftarrow w_i \cdot \exp(-\alpha_b \cdot y_i \cdot h_b(\mathbf{x}_i))$
6. Normalize weights and repeat

Mispredicted samples get higher weights, so the next tree focuses on them.

### Where does $\alpha_b$ come from?

AdaBoost is greedy minimization of the **exponential loss** $\sum_i w_i\exp(-\alpha\, y_i h_b(\mathbf x_i))$. Split the sum into correct ($y_i h_b=+1$) and wrong ($y_i h_b=-1$) terms — their weights are $(1-\epsilon_b)$ and $\epsilon_b$:

$$
(1-\epsilon_b)e^{-\alpha} + \epsilon_b e^{\alpha}.
$$

Differentiate w.r.t. $\alpha$ and set to zero: $-(1-\epsilon_b)e^{-\alpha}+\epsilon_b e^{\alpha}=0 \Rightarrow e^{2\alpha}=\frac{1-\epsilon_b}{\epsilon_b}$, giving

$$
\alpha_b = \tfrac{1}{2}\ln\frac{1-\epsilon_b}{\epsilon_b}.
$$

A learner better than chance ($\epsilon_b<0.5$) gets $\alpha_b>0$; an accurate learner ($\epsilon_b\to0$) gets a large weight; a coin-flip ($\epsilon_b=0.5$) gets $\alpha_b=0$ — ignored.

### Worked example: one AdaBoost round

10 points, uniform weights $w_i=0.1$. A stump misclassifies **2** of them, so $\epsilon_1 = 2(0.1) = 0.2$.

$$
\alpha_1 = \tfrac12\ln\frac{0.8}{0.2} = \tfrac12\ln 4 = 0.693.
$$

**Reweight** $w_i \leftarrow w_i e^{\mp\alpha_1}$: correct points $\times e^{-0.693}=0.5$, wrong points $\times e^{+0.693}=2.0$:

- 8 correct: $0.1\times0.5 = 0.05$ each
- 2 wrong: $0.1\times2.0 = 0.20$ each

Sum $= 8(0.05)+2(0.20) = 0.8$. **Normalize** (divide by 0.8):

- correct: $0.0625$ each, wrong: $0.25$ each — check $8(0.0625)+2(0.25)=1$ ✓.

Notice the two misclassified points now hold $2(0.25)=\mathbf{0.5}$ of the total weight. This is a general AdaBoost identity: after reweighting, the just-trained stump has *exactly* $0.5$ weighted error on the new distribution — so the next stump is forced to look elsewhere.

```python
from sklearn.ensemble import AdaBoostClassifier
from sklearn.tree import DecisionTreeClassifier

ada = AdaBoostClassifier(
    estimator=DecisionTreeClassifier(max_depth=1),  # "stump" — 1 split
    n_estimators=200,
    learning_rate=1.0,
    random_state=42
)
ada.fit(X_train, y_train)
print(f"AdaBoost accuracy: {ada.score(X_test, y_test):.3f}")
```

## Gradient Boosting

Generalizes boosting to any differentiable loss function. Each new tree fits the **negative gradient** (residuals) of the loss:

$$
r_i^{(b)} = -\frac{\partial \mathcal{L}(y_i, \hat{f}_{b-1}(\mathbf{x}_i))}{\partial \hat{f}_{b-1}(\mathbf{x}_i)}
$$

For MSE loss, this is simply the residual $y_i - \hat{f}_{b-1}(\mathbf{x}_i)$.

```python
from sklearn.ensemble import GradientBoostingClassifier

gbm = GradientBoostingClassifier(
    n_estimators=200,
    max_depth=4,
    learning_rate=0.1,
    subsample=0.8,       # stochastic gradient boosting
    min_samples_leaf=10,
    random_state=42
)
gbm.fit(X_train, y_train)
print(f"GBM accuracy: {gbm.score(X_test, y_test):.3f}")
```

<Callout type="info" title="Learning rate vs n_estimators">
  These are inversely related. Lower learning rate → need more trees → better generalization. The sweet spot: $\eta = 0.01$-$0.1$ with 500-2000 trees. Always use early stopping to find the optimal number of trees.
</Callout>

## XGBoost and LightGBM

Modern gradient boosting implementations with significant speedups:

### XGBoost
- Regularized objective (L1 + L2)
- Sparse-aware algorithms
- GPU training support

### LightGBM
- Histogram-based splitting (faster)
- Leaf-wise growth (better accuracy)
- Native categorical feature support

```python
import xgboost as xgb
import lightgbm as lgb

# XGBoost
xgb_model = xgb.XGBClassifier(
    n_estimators=500,
    max_depth=6,
    learning_rate=0.05,
    subsample=0.8,
    colsample_bytree=0.8,
    eval_metric='logloss',
    early_stopping_rounds=50
)
xgb_model.fit(X_train, y_train, eval_set=[(X_test, y_test)], verbose=False)

# LightGBM
lgb_model = lgb.LGBMClassifier(
    n_estimators=500,
    max_depth=6,
    learning_rate=0.05,
    subsample=0.8,
    colsample_bytree=0.8,
    early_stopping_round=50
)
lgb_model.fit(X_train, y_train, eval_set=[(X_test, y_test)])
```

## Boosting vs Bagging

| Property | Bagging | Boosting |
|----------|---------|----------|
| Training | Parallel | Sequential |
| Bias reduction | No | Yes |
| Variance reduction | Yes | Yes (via shrinkage) |
| Overfitting risk | Low | High (if too many trees) |
| Speed | Fast (parallel) | Slow (sequential) |
| Sensitive to noise | No | Yes |

<Callout type="warning" title="Boosting overfits easily">
  Boosting is more powerful than bagging but also more prone to overfitting, especially with noisy data. Always use:
  - Low learning rate (0.01-0.1)
  - Early stopping
  - Subsample (0.8) for stochastic boosting
  - Tree constraints (max_depth, min_samples_leaf)
</Callout>

## When to use what

| Scenario | Best choice |
|----------|-------------|
| Tabular data, default baseline | Random Forest |
| Tabular data, need best accuracy | XGBoost / LightGBM |
| Very noisy data | Random Forest (robust) |
| Need fast inference | Random Forest (parallel) |
| Kaggle competition | LightGBM or XGBoost |
| Text classification | Linear SVM or Naive Bayes |

## Common mistakes

1. **Too many trees without early stopping** — Boosting will keep improving training accuracy long past the point of overfitting. Always use early stopping.
2. **High learning rate** — $\eta > 0.3$ is usually too aggressive. Use 0.01-0.1.
3. **Ignoring categorical features** — XGBoost/LightGBM handle categoricals natively. Don't one-hot encode everything.

## Key takeaways

- **Boosting** builds models sequentially, each fixing the last ensemble's mistakes — cutting **bias**.
- **AdaBoost** reweights errors; **gradient boosting** fits residual gradients.
- **XGBoost/LightGBM** are fast, regularized gradient boosting — top tabular performers.
- Lower `learning_rate` + more trees generalizes better; boosting can overfit if unregularized.
