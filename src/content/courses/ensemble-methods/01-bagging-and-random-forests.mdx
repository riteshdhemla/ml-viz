# Bagging & Random Forests

A single decision tree overfits easily — it's high-variance. **Bagging** (Bootstrap Aggregating) trains many trees on random subsets of data and averages their predictions, dramatically reducing variance. In [project-loop](/wiki/ml-project-loop) terms, an ensemble is a **hypothesis-space** move: instead of one model, your function family becomes *averages of many* — strictly more expressive, and much lower variance.

<WikiLink slug="ml-project-loop" title="The ML Project Loop" />

**Real-world examples:** Credit scoring, customer churn prediction, medical diagnosis, any tabular data task.

## Bagging (Bootstrap Aggregating)

1. Create $B$ bootstrap samples (sample with replacement, same size as original)
2. Train a decision tree on each sample
3. **Classification:** majority vote. **Regression:** average predictions.

Each tree sees a different "view" of the data. Some points appear multiple times, others not at all (~37% are left out per tree). Averaging many diverse trees reduces variance without increasing bias.

$$
\hat{f}_{\text{bag}}(\mathbf{x}) = \frac{1}{B} \sum_{b=1}^{B} T_b(\mathbf{x})
$$

<Callout type="tip" title="Why bagging works">
  Different bootstrap samples produce *different* trees, and averaging diverse estimates cancels their individual noise — like polling: one poll is noisy, but averaging 1000 polls gives a reliable estimate. If the trees were perfectly uncorrelated, the variance of the average would drop by a full factor of $B$; the next section shows how close bagging actually gets.
</Callout>

### How much does variance actually drop?

The "factor of $B$" only holds if the trees are *perfectly uncorrelated*, but bagged trees aren't, since they share most of their data. For $B$ identically-distributed trees each with variance $\sigma^2$ and **pairwise correlation $\rho$**, the variance of their average is:

$$
\text{Var}\!\left(\frac{1}{B}\sum_b T_b\right) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2.
$$

Two terms with very different behavior:

- The second term $\frac{1-\rho}{B}\sigma^2$ vanishes as $B\to\infty$ — **adding more trees** kills it.
- The first term $\rho\sigma^2$ is a **floor** that more trees cannot touch.

This is the key insight behind random forests: once you have enough trees, the only way to reduce variance further is to **lower $\rho$**. Bagging alone leaves $\rho$ high (trees all latch onto the same dominant feature); random feature subsets at each split push $\rho$ down, lowering the floor. So RF attacks the term bagging can't.

### Worked example

5 trees predict [cat, dog, cat, cat, dog] for a new image. Majority vote: **cat** (3 vs 2).

```python
# The idiom (for your own X_train / y_train / X_test / y_test):
from sklearn.ensemble import BaggingClassifier
from sklearn.tree import DecisionTreeClassifier

bag = BaggingClassifier(
    estimator=DecisionTreeClassifier(max_depth=None),
    n_estimators=100,
    max_samples=0.8,       # each tree sees 80% of data
    max_features=1.0,      # all features
    bootstrap=True,
    random_state=42
)
bag.fit(X_train, y_train)
print(f"Bagging accuracy: {bag.score(X_test, y_test):.3f}")
```

## Random Forests

Random Forests improve on bagging by adding **feature randomization**: at each split, only consider a random subset of $m$ features.

This decorrelates the trees further. They can't all rely on the same dominant feature:

| Task | Default $m$ |
|------|------------|
| Classification | $\sqrt{d}$ |
| Regression | $d/3$ |

$$
\hat{f}_{\text{RF}}(\mathbf{x}) = \frac{1}{B} \sum_{b=1}^{B} T_b(\mathbf{x}, \theta_b)
$$

where $\theta_b$ are the random feature subsets for tree $b$.

```python
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=100,       # number of trees
    max_depth=10,           # limit tree depth
    max_features='sqrt',    # √d features per split
    min_samples_leaf=5,     # minimum samples in leaf
    random_state=42,
    n_jobs=-1               # use all CPU cores
)
rf.fit(X_train, y_train)
print(f"RF accuracy: {rf.score(X_test, y_test):.3f}")
```

## Feature importance

Two main methods:

### Mean Decrease in Impurity (MDI)

Sum the impurity decrease at each split across all trees, weighted by the number of samples reaching that split.

```python
import numpy as np

importances = rf.feature_importances_
for i in np.argsort(importances)[::-1][:5]:
    print(f"Feature {i}: {importances[i]:.3f}")
```

### Permutation importance (more reliable)

Shuffle each feature and measure accuracy drop:

```python
from sklearn.inspection import permutation_importance

result = permutation_importance(rf, X_test, y_test, n_repeats=10, random_state=42)
for i in np.argsort(result.importances_mean)[::-1][:5]:
    print(f"Feature {i}: {result.importances_mean[i]:.3f} ± {result.importances_std[i]:.3f}")
```

<Callout type="info" title="MDI vs Permutation importance">
  MDI can be biased toward high-cardinality features (e.g., ID numbers). Permutation importance is more reliable but slower. Use permutation importance for final analysis, MDI for quick exploration.
</Callout>

## Out-of-Bag (OOB) evaluation

**Where does "~37%" come from?** A bootstrap sample draws $n$ rows with replacement. The chance a specific row is *not* picked on one draw is $1-\tfrac1n$, and draws are independent, so the chance it's missed by all $n$ draws is:

$$
\left(1 - \frac{1}{n}\right)^{n} \;\xrightarrow{\;n\to\infty\;}\; e^{-1} \approx 0.368.
$$

So each tree leaves out about **37%** of the rows (e.g. $n=100$ gives $0.366$). Those out-of-bag rows were never seen by that tree, so we can use them as a built-in validation set — no cross-validation needed:

```python
rf = RandomForestClassifier(n_estimators=100, oob_score=True, random_state=42)
rf.fit(X_train, y_train)
print(f"OOB accuracy: {rf.oob_score_:.3f}")  # ~same as test accuracy
```

**What to notice:**

- **Frame 3 — the formula holds, and the floor is visible.** Measured ensemble variance tracks $\rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$ across a sweep of $B$. By $B = 40$ the second term is down to 0.02 while the first sits immovably at 0.18, so more trees buy essentially nothing.
- **Frame 4 — averaging does not touch the bias.** Single tree and 40-tree ensemble have the *same* bias at the probe point; only the variance collapses. Averaging is linear, so bagging cannot fix a systematically wrong model — only an unstable one. That is the gap boosting exists to attack.
- **Frame 5 — what random forests actually trade.** Sampling 2 of 5 features drops $\rho$ from 0.172 to 0.072 as promised, but per-tree variance $\sigma^2$ *rises* from 1.05 to 1.83, because a tree denied the best split is a worse estimator. The floor $\rho\sigma^2$ falls 28% anyway. RF deliberately accepts a worse individual model to buy decorrelation that more trees can exploit.
- **Frame 6 — OOB against a real test set.** Over 45 datasets the OOB error is +0.186 ± 0.111 above the held-out test error, about 6% — close enough to use, and biased in the conservative direction because an OOB prediction averages only the ~22 trees that excluded that row.

## Strengths and weaknesses

| ✅ Strengths | ❌ Weaknesses |
|-------------|--------------|
| Robust to overfitting | Less interpretable than single tree |
| Handles high-dimensional data | Can be slow for large datasets |
| Parallelizable | Cannot extrapolate (interpolation only) |
| Provides feature importance | Struggles with very sparse data |
| Minimal hyperparameter tuning | Black-box compared to single tree |
| Handles missing values | |

<Callout type="warning" title="Random Forests are the best tabular baseline">
  If you have structured/tabular data and don't know where to start, try Random Forests first. They require minimal tuning, are robust to overfitting, and provide feature importance. Only move to gradient boosting if you need more accuracy.
</Callout>

## Common mistakes

1. **Leaving trees completely unconstrained** — cap complexity one way or the other: either `max_depth=10`, or if you keep `max_depth=None`, set `min_samples_leaf=5` so leaves can't chase single points.
2. **Using too few trees** — 10 trees is not enough. Use 100-500. More trees rarely hurt (diminishing returns), but few trees give noisy estimates.
3. **Ignoring feature scaling** — Random Forests don't need scaling! They're invariant to monotonic transformations. Don't waste time preprocessing.

## Key takeaways

- **Bagging** trains models on bootstrap samples and averages them, cutting **variance**.
- **Random forests** add per-split feature randomness to decorrelate the trees.
- **Out-of-bag** rows give a built-in validation score.
- Prefer **permutation importance** over impurity-based importance for reliability.
