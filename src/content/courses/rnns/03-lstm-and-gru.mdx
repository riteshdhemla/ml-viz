# LSTM & GRU: Gated Memory

The vanishing gradient problem killed long-range learning in vanilla RNNs. The **Long Short-Term Memory (LSTM)** cell, introduced by Hochreiter & Schmidhuber in 1997, fixed it with two ideas: a separate **cell state** that acts as a gradient highway, and **gates** that learn what to remember, forget, and output.

**Real-world examples:** Before Transformers took over (2017+), LSTMs powered Google Translate, Siri/Alexa speech recognition, handwriting recognition, and most time-series forecasting. They remain strong on small datasets and streaming tasks.

## The key innovation: the cell state

An LSTM carries **two** vectors between steps:

- $\mathbf{h}_t$ — the hidden state (the output, the "working memory")
- $\mathbf{c}_t$ — the **cell state** (the long-term memory)

The cell state is updated almost entirely by **addition**, not repeated matrix multiplication:

$$
\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t
$$

That additive path is the gradient highway. Because $\partial \mathbf{c}_t / \partial \mathbf{c}_{t-1} \approx \mathbf{f}_t$ (a gate near 1, not a fixed weight matrix), gradients can flow across hundreds of steps without vanishing.

<Callout type="tip" title="Intuition">
  Think of the cell state as a conveyor belt running straight through the whole sequence. The gates are valves: the forget gate decides what falls off the belt, the input gate decides what new items get placed on it, and the output gate decides what to read off it right now. Information can ride the belt untouched for a long time.
</Callout>

## The three gates

Each gate is a small sigmoid layer producing values in $(0, 1)$ — think of them as soft switches, where 0 = "block completely" and 1 = "let everything through." All three look at the previous hidden state $\mathbf{h}_{t-1}$ and the current input $\mathbf{x}_t$.

**1. Forget gate** — what to erase from the cell state:
$$
\mathbf{f}_t = \sigma(W_f[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_f)
$$

**2. Input gate** — what new information to write:
$$
\mathbf{i}_t = \sigma(W_i[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_i)
$$
$$
\tilde{\mathbf{c}}_t = \tanh(W_c[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_c) \quad\text{(candidate values)}
$$

**3. Output gate** — what to expose as the hidden state:
$$
\mathbf{o}_t = \sigma(W_o[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_o)
$$

And the state updates:
$$
\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t \qquad \mathbf{h}_t = \mathbf{o}_t \odot \tanh(\mathbf{c}_t)
$$

($\odot$ is element-wise multiplication; $[\cdot,\cdot]$ is concatenation.)

| Gate | Question it answers | Output ≈ 0 | Output ≈ 1 |
|------|--------------------|------------|------------|
| Forget $\mathbf{f}_t$ | Keep old memory? | erase it | keep it |
| Input $\mathbf{i}_t$ | Store new info? | ignore input | write it |
| Output $\mathbf{o}_t$ | Reveal memory now? | stay silent | expose it |

### Worked example — the forget gate in action

Imagine a single cell tracking grammatical subject *number* (singular vs plural) while reading "The **keys** to the cabinet ...". At the word "keys" the input gate writes "plural" to the cell. As irrelevant words ("to", "the", "cabinet") stream past, the forget gate stays near 1 — **preserving** "plural" — so that many steps later the model conjugates "**are** on the table," not "is." A vanilla RNN would have forgotten the subject by then.

### A full LSTM timestep, by hand

Let's run **one** timestep of a scalar LSTM ($D = 1$ input, $H = 1$ hidden) with small explicit numbers so every gate is hand-checkable. The concatenated input is $z = [\,h_{t-1},\, x_t\,]$, and each gate has weights $[W_h, W_x]$ and a bias.

**Inputs:** $h_{t-1} = 0$, $x_t = 1$, $c_{t-1} = 2$.

**Weights** (chosen to keep the sums simple):

| Gate | $W_h$ | $W_x$ | bias |
|------|-------|-------|------|
| Forget $f$ | 0 | 0 | $+2$ |
| Input $i$ | 0 | 1 | $-1$ |
| Candidate $\tilde{c}$ | 0 | 1 | 0 |
| Output $o$ | 0 | 1 | 0 |

**Step 1 — pre-activations** (each is $W_h h_{t-1} + W_x x_t + b$):

$$
z_f = 0\cdot 0 + 0\cdot 1 + 2 = 2,\quad
z_i = 0\cdot 0 + 1\cdot 1 - 1 = 0,\quad
z_{\tilde c} = 1,\quad
z_o = 1
$$

**Step 2 — apply the nonlinearities** ($\sigma$ on the gates, $\tanh$ on the candidate):

$$
\begin{aligned}
f_t &= \sigma(2) = \tfrac{1}{1+e^{-2}} \approx 0.881 \\
i_t &= \sigma(0) = 0.5 \\
\tilde{c}_t &= \tanh(1) \approx 0.762 \\
o_t &= \sigma(1) \approx 0.731
\end{aligned}
$$

**Step 3 — update the cell state** (the additive rule):

$$
c_t = f_t\, c_{t-1} + i_t\, \tilde{c}_t
= 0.881\times 2 + 0.5\times 0.762
= 1.762 + 0.381 = \boxed{2.142}
$$

**Step 4 — emit the hidden state:**

$$
h_t = o_t \tanh(c_t) = 0.731 \times \tanh(2.142) = 0.731 \times 0.973 = \boxed{0.711}
$$

So this cell mostly **kept** its old memory ($f_t \approx 0.88$, carrying $1.76$ of the old $2.0$ forward) and wrote a small amount of new content. These exact numbers are reproduced and verified in the companion notebook.

```python
import numpy as np

def sigmoid(z): return 1 / (1 + np.exp(-z))

# One LSTM step, fully spelled out
def lstm_step(x, h, c, params):
    z = np.concatenate([h, x])
    f = sigmoid(params['Wf'] @ z + params['bf'])     # forget
    i = sigmoid(params['Wi'] @ z + params['bi'])     # input
    c_tilde = np.tanh(params['Wc'] @ z + params['bc'])  # candidate
    o = sigmoid(params['Wo'] @ z + params['bo'])     # output
    c = f * c + i * c_tilde                           # update cell (additive!)
    h = o * np.tanh(c)                                # update hidden
    return h, c
```

## Using PyTorch's LSTM

```python
import torch
import torch.nn as nn

lstm = nn.LSTM(input_size=10, hidden_size=20, num_layers=2, batch_first=True)
x = torch.randn(4, 15, 10)                # (batch, seq_len, features)
output, (h_n, c_n) = lstm(x)

print(output.shape)   # (4, 15, 20) — hidden state per step
print(h_n.shape)      # (2, 4, 20) — final hidden, per layer
print(c_n.shape)      # (2, 4, 20) — final cell state, per layer
```

## GRU: the leaner cousin

The **Gated Recurrent Unit (GRU)** (Cho et al., 2014) merges the cell and hidden state into one and uses just **two** gates — a **reset** gate $\mathbf{r}_t$ and an **update** gate $\mathbf{z}_t$:

$$
\mathbf{z}_t = \sigma(W_z[\mathbf{h}_{t-1}, \mathbf{x}_t]) \qquad \mathbf{r}_t = \sigma(W_r[\mathbf{h}_{t-1}, \mathbf{x}_t])
$$
$$
\tilde{\mathbf{h}}_t = \tanh(W_h[\mathbf{r}_t \odot \mathbf{h}_{t-1}, \mathbf{x}_t])
$$
$$
\mathbf{h}_t = (1 - \mathbf{z}_t)\odot \mathbf{h}_{t-1} + \mathbf{z}_t \odot \tilde{\mathbf{h}}_t
$$

The update gate $\mathbf{z}_t$ does the job of the LSTM's forget *and* input gates at once: it interpolates between keeping the old state and writing the new candidate.

### Counting the parameters

Each gate is one linear layer over the concatenation $[\mathbf{h}_{t-1}, \mathbf{x}_t]$. With input dimension $D$ and hidden size $H$, that layer has:

$$
\underbrace{H\times D}_{W_x} + \underbrace{H\times H}_{W_h} + \underbrace{H}_{\text{bias}} \;=\; H(D + H + 1) \text{ parameters per gate.}
$$

An **LSTM has 4 such layers** (forget, input, candidate, output), a **GRU has 3** (reset, update, candidate):

$$
P_{\text{LSTM}} = 4\,H(D + H + 1), \qquad P_{\text{GRU}} = 3\,H(D + H + 1).
$$

**Concrete count** for $D = 10$, $H = 20$. One gate is $20(10 + 20 + 1) = 20\times 31 = 620$ parameters, so:

$$
P_{\text{LSTM}} = 4\times 620 = 2{,}480, \qquad P_{\text{GRU}} = 3\times 620 = 1{,}860.
$$

The GRU has exactly $1860/2480 = 0.75$ of the parameters — **25% fewer**, because it drops one of the four gate layers. (Both are also verified in the notebook.)

| | LSTM | GRU |
|---|------|-----|
| Gates | 3 + candidate (4 layers) | 2 + candidate (3 layers) |
| State vectors | 2 ($\mathbf{h}$ and $\mathbf{c}$) | 1 ($\mathbf{h}$) |
| Parameters (D=10, H=20) | 2,480 | 1,860 (25% fewer) |
| Speed | Slower | Faster |
| Typical edge | Long, complex sequences | Smaller data, faster training |

<Callout type="info" title="Which should I use?">
  There is no universal winner — they perform comparably on most tasks. Start with a **GRU** (fewer parameters, faster, less prone to overfit on small data). Switch to **LSTM** if you have lots of data and very long dependencies. Try both and let validation loss decide.
</Callout>

## Why gates beat plain RNNs

Differentiate the additive cell update with respect to the previous cell state. Holding the gates fixed (they depend on $\mathbf{h}_{t-1}$, but that second-order path is small), the dominant term is strikingly simple:

$$
\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t
\quad\Longrightarrow\quad
\frac{\partial \mathbf{c}_t}{\partial \mathbf{c}_{t-1}} \approx \mathbf{f}_t.
$$

Chaining this back over $T$ steps multiplies the **forget gates** together:

$$
\frac{\partial \mathbf{c}_T}{\partial \mathbf{c}_0} \approx \prod_{t=1}^{T} \mathbf{f}_t.
$$

Compare with the vanilla RNN, where every step multiplies by $W_{hh}^\top \,\mathrm{diag}(\tanh')$ — so the gradient scales like $\big(W_{hh}\big)^{T}$ and a single eigenvalue below 1 makes it **vanish** exponentially.

**Concrete contrast over $T = 50$ steps.** If the LSTM keeps its forget gate at $f = 0.95$, the surviving gradient is $0.95^{50} \approx 0.077$. A vanilla RNN with an effective per-step factor of $0.9$ gives $0.9^{50} \approx 0.005$ — about **15× smaller**. Push the forget gate to $f = 0.99$ and $0.99^{50} \approx 0.61$: nearly **two-thirds of the gradient survives** 50 steps. That is the gradient highway.

<Callout type="success" title="The gradient highway">
  The additive cell update $\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \dots$ means the gradient flowing back through the cell state is multiplied by the forget gate (often ≈ 1), **not** by a weight matrix raised to a power. That is precisely what lets LSTMs and GRUs learn dependencies hundreds of steps long where a vanilla RNN tops out around 10–20.
</Callout>

## Common mistakes

1. **Initializing the forget-gate bias to 0** — set $\mathbf{b}_f$ to **+1 or +2** so the cell defaults to *remembering* early in training. This is a well-known practical trick.
2. **Stacking too many layers** on small data — 1–2 layers is usually enough; more overfits.
3. **Reaching for an LSTM when attention is better** — for long documents, Transformers (next course) generally beat any RNN. LSTMs shine on small data and streaming.

## Key takeaways

- LSTMs add a **cell state** updated by addition — a gradient highway for long memory.
- Three **gates** (forget/input/output) learn what to keep, write, and reveal.
- **GRU** merges them into two gates and one state — fewer parameters, similar performance.
- Initialize the forget-gate bias positive so the cell defaults to remembering.
