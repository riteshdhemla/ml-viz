# Recurrent Neural Networks

A feed-forward network maps a fixed-size input to a fixed-size output. But language, audio, stock prices, and DNA are **sequences** — their length varies and their order matters. A Recurrent Neural Network (RNN) processes a sequence one element at a time, carrying a **hidden state** that summarizes everything it has seen so far.

**Real-world examples:** Language modeling, machine translation, speech recognition, time-series forecasting, sentiment analysis, music generation.

## The core idea: a loop

A feed-forward layer computes $\mathbf{y} = f(W\mathbf{x})$ once. An RNN applies the *same* layer repeatedly, feeding its own previous output back in as extra input:

$$
\mathbf{h}_t = \tanh\!\left(W_{xh}\,\mathbf{x}_t + W_{hh}\,\mathbf{h}_{t-1} + \mathbf{b}_h\right)
$$

$$
\mathbf{y}_t = W_{hy}\,\mathbf{h}_t + \mathbf{b}_y
$$

- $\mathbf{x}_t$ — input at time step $t$ (e.g. the embedding of the $t$-th word), a $D$-vector
- $\mathbf{h}_t$ — hidden state at time $t$, the network's "memory", an $H$-vector
- $\mathbf{h}_{t-1}$ — hidden state from the previous step
- $W_{xh}$ ($H\times D$), $W_{hh}$ ($H\times H$), $W_{hy}$ ($O\times H$) — weight matrices, **shared across all time steps**

<Callout type="tip" title="Intuition">
  The hidden state is like reading a book and keeping a running summary in your head. Each new sentence ($\mathbf{x}_t$) updates your understanding ($\mathbf{h}_t$) based on what you already knew ($\mathbf{h}_{t-1}$). You never re-read the whole book — the summary carries the context forward.
</Callout>

### Why the hidden state *is* memory

Unroll the recurrence by substituting $\mathbf{h}_{t-1}$, then $\mathbf{h}_{t-2}$, and so on:

$$
\mathbf{h}_t = \tanh\!\Big(W_{xh}\mathbf{x}_t + W_{hh}\,\underbrace{\tanh(W_{xh}\mathbf{x}_{t-1} + W_{hh}\mathbf{h}_{t-2} + \mathbf{b}_h)}_{\mathbf{h}_{t-1}} + \mathbf{b}_h\Big)
$$

Every past input $\mathbf{x}_1,\dots,\mathbf{x}_t$ has left a fingerprint inside $\mathbf{h}_t$. There is no separate storage buffer — the *single fixed-size vector* $\mathbf{h}_t$ is a lossy compression of the entire prefix. That is exactly why we call it memory: change an earlier input and $\mathbf{h}_t$ changes too.

Crucially, every box is the **same** set of weights. This **parameter sharing** is why an RNN can handle a sequence of *any* length with a fixed number of parameters — and why a pattern learned at position 2 transfers to position 200.

## Weight sharing matters

| Property | Feed-forward net | RNN |
|----------|------------------|-----|
| Input length | Fixed | Variable |
| Parameters grow with length? | Yes | No (shared) |
| Sees order of inputs? | No | Yes |
| Has memory of past? | No | Yes (hidden state) |

## How many parameters? Counting an RNN cell

Because the weights are shared, the parameter count is **independent of sequence length**. For input size $D$, hidden size $H$, output size $O$:

| Tensor | Shape | Count |
|--------|-------|-------|
| $W_{xh}$ | $H\times D$ | $HD$ |
| $W_{hh}$ | $H\times H$ | $H^2$ |
| $\mathbf{b}_h$ | $H$ | $H$ |
| $W_{hy}$ | $O\times H$ | $OH$ |
| $\mathbf{b}_y$ | $O$ | $O$ |

$$
\text{total} = \underbrace{HD + H^2 + H}_{\text{recurrent cell}} + \underbrace{OH + O}_{\text{output head}}
$$

**Worked count** for $D=3,\;H=4,\;O=2$:

$$
\underbrace{4\cdot 3}_{12} + \underbrace{4^2}_{16} + \underbrace{4}_{4} + \underbrace{2\cdot 4}_{8} + \underbrace{2}_{2} = 42
$$

The recurrent cell alone (the part reused at every step) is $HD + H^2 + H = 12 + 16 + 4 = 32$ parameters. Process a length-3 or a length-3000 sequence — it is still these same 32 numbers.

## Worked forward pass — two timesteps by hand

Let's run the full recurrence with $D=2$ input, $H=2$ hidden, $O=1$ output, and tiny explicit weights:

$$
W_{xh}=\begin{bmatrix}0.5 & -0.3\\ 0.1 & 0.4\end{bmatrix},\quad
W_{hh}=\begin{bmatrix}0.2 & 0\\ 0 & 0.2\end{bmatrix},\quad
\mathbf{b}_h=\begin{bmatrix}0\\0\end{bmatrix},\quad
W_{hy}=\begin{bmatrix}1 & -1\end{bmatrix},\quad b_y=0
$$

Start from $\mathbf{h}_0 = \begin{bmatrix}0\\0\end{bmatrix}$ and feed $\mathbf{x}_1=\begin{bmatrix}1\\2\end{bmatrix}$, then $\mathbf{x}_2=\begin{bmatrix}-1\\1\end{bmatrix}$.

**Step 1.** Since $\mathbf{h}_0=\mathbf{0}$, the $W_{hh}\mathbf{h}_0$ term vanishes:

$$
W_{xh}\mathbf{x}_1=\begin{bmatrix}0.5(1)-0.3(2)\\ 0.1(1)+0.4(2)\end{bmatrix}=\begin{bmatrix}-0.1\\ 0.9\end{bmatrix}
$$
$$
\mathbf{h}_1=\tanh\!\begin{bmatrix}-0.1\\ 0.9\end{bmatrix}=\begin{bmatrix}\tanh(-0.1)\\ \tanh(0.9)\end{bmatrix}=\begin{bmatrix}-0.0997\\ 0.7163\end{bmatrix}
$$
$$
y_1 = W_{hy}\mathbf{h}_1 = 1(-0.0997) + (-1)(0.7163) = -0.8160
$$

**Step 2.** Now the previous hidden state feeds back in. First the two contributions to the pre-activation:

$$
W_{xh}\mathbf{x}_2=\begin{bmatrix}0.5(-1)-0.3(1)\\ 0.1(-1)+0.4(1)\end{bmatrix}=\begin{bmatrix}-0.8\\ 0.3\end{bmatrix},\qquad
W_{hh}\mathbf{h}_1=0.2\,\mathbf{h}_1=\begin{bmatrix}-0.0199\\ 0.1433\end{bmatrix}
$$
$$
\text{pre}_2 = \begin{bmatrix}-0.8\\ 0.3\end{bmatrix}+\begin{bmatrix}-0.0199\\ 0.1433\end{bmatrix}=\begin{bmatrix}-0.8199\\ 0.4433\end{bmatrix}
$$
$$
\mathbf{h}_2=\tanh\!\begin{bmatrix}-0.8199\\ 0.4433\end{bmatrix}=\begin{bmatrix}-0.6750\\ 0.4163\end{bmatrix}
$$
$$
y_2 = 1(-0.6750) + (-1)(0.4163) = -1.0914
$$

Notice the $W_{hh}\mathbf{h}_1$ term: $\mathbf{h}_2$ depends on $\mathbf{x}_1$ *through* $\mathbf{h}_1$. That feedback path is the memory channel. The notebook recomputes every number above and asserts they match.

### Worked example — a 1-D hidden state

To see memory accumulate over more steps, drop to a scalar: $W_{xh}=0.5$, $W_{hh}=0.9$, $b_h=0$, $h_0=0$, inputs $x = [1, 1, 1]$.

$$
h_1 = \tanh(0.5\cdot 1 + 0.9\cdot 0) = \tanh(0.5) = 0.462
$$
$$
h_2 = \tanh(0.5\cdot 1 + 0.9\cdot 0.462) = \tanh(0.916) = 0.724
$$
$$
h_3 = \tanh(0.5\cdot 1 + 0.9\cdot 0.724) = \tanh(1.152) = 0.818
$$

The hidden state *accumulates* — each step builds on the last. The $\tanh$ keeps it bounded in $(-1, 1)$ so it cannot blow up within a step.

## Sequence-to-what? The four shapes

RNNs flex to different tasks depending on how many inputs and outputs you wire up:

| Pattern | Inputs → Outputs | Example |
|---------|------------------|---------|
| **one-to-many** | 1 → N | Image → caption |
| **many-to-one** | N → 1 | Review → sentiment label |
| **many-to-many (aligned)** | N → N | Part-of-speech tagging |
| **many-to-many (seq2seq)** | N → M | Translation (encoder–decoder) |

### From scratch in code

The same recurrence, with a small random RNN over a length-5 sequence:

```python
import numpy as np

def rnn_step(x, h, W_xh, W_hh, b_h):
    return np.tanh(W_xh @ x + W_hh @ h + b_h)

# A tiny RNN: 3-dim input, 4-dim hidden state
np.random.seed(0)
W_xh = np.random.randn(4, 3) * 0.1
W_hh = np.random.randn(4, 4) * 0.1
b_h  = np.zeros(4)

h = np.zeros(4)                       # initial hidden state
sequence = [np.random.randn(3) for _ in range(5)]

for t, x in enumerate(sequence):
    h = rnn_step(x, h, W_xh, W_hh, b_h)
    print(f"t={t}  h = {np.round(h, 3)}")
```

## Using PyTorch's built-in RNN

```python
import torch
import torch.nn as nn

rnn = nn.RNN(input_size=3, hidden_size=4, batch_first=True)

# (batch=2, seq_len=5, features=3)
x = torch.randn(2, 5, 3)
output, h_n = rnn(x)

print(output.shape)  # (2, 5, 4) — hidden state at every time step
print(h_n.shape)     # (1, 2, 4) — final hidden state only
```

<Callout type="info" title="output vs h_n">
  `output` gives you the hidden state at *every* step (use for tagging / seq2seq). `h_n` is just the *final* hidden state (use for classification, e.g. sentiment). They share the last step: `output[:, -1, :] == h_n[0]`.
</Callout>

## Strengths and limits

**Strengths:** handle variable-length input, model order and context, compact (shared weights), natural fit for streaming/online data.

**Limits:**
1. **Sequential by nature** — step $t$ needs $\mathbf{h}_{t-1}$, so training cannot parallelize across time.
2. **Short memory** — vanilla RNNs struggle to connect events far apart (next lesson).
3. **Vanishing/exploding gradients** — repeated multiplication by $W_{hh}$ during training destabilizes learning.

<Callout type="warning" title="Vanilla RNNs forget fast">
  In practice a plain RNN reliably remembers only ~10–20 steps. The "vanishing gradient" problem — covered next — is *the* reason LSTMs and GRUs were invented.
</Callout>

## Common mistakes

1. **Forgetting to reset the hidden state** between independent sequences — context leaks across unrelated examples.
2. **Not detaching/truncating** the hidden state across long sequences — backprop grows unbounded in memory.
3. **Feeding raw token IDs** instead of embeddings — RNNs expect continuous vectors, not category indices.

## Key takeaways

- An RNN carries a **hidden state** that summarizes the sequence seen so far.
- **Weight sharing** across time steps handles variable-length input with fixed parameters.
- Output wiring (one/many in/out) adapts it to tagging, classification, or seq2seq.
- Vanilla RNNs reliably remember only ~10–20 steps.
