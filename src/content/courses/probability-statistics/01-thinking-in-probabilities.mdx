# Thinking in Probabilities

Machine learning is the business of making decisions under uncertainty — a model never *knows* the label, it *believes* it with some strength. Probability is the language those beliefs are written in. Two stages of the [ML project loop](/wiki/ml-project-loop) lean hardest on it: the **objective** (almost every loss is a negative log-likelihood) and **evaluation** (every confidence interval and p-value). Before meeting the famous [distributions](/courses/probability-statistics/02-probability-distributions), it pays to nail down the small set of words everything else is built from.

<WikiLink slug="ml-project-loop" title="The ML Project Loop" />

## Sample spaces and events

A **sample space** $\Omega$ is the set of everything that could happen in one run of an experiment:

- One coin flip: $\Omega = \{H, T\}$
- One die roll: $\Omega = \{1, 2, 3, 4, 5, 6\}$
- Tomorrow's temperature: $\Omega = \mathbb{R}$ (uncountably many outcomes!)

An **event** is any subset of outcomes you might care about: "the roll is even" is the event $A = \{2, 4, 6\}$. A probability function $P$ assigns each event a number, subject to three rules (the Kolmogorov axioms):

1. $P(A) \ge 0$ — no negative beliefs
2. $P(\Omega) = 1$ — *something* happens
3. If $A$ and $B$ can't both happen, $P(A \cup B) = P(A) + P(B)$ — probabilities of exclusive events add

That's the entire rulebook. Everything else — Bayes' theorem, likelihoods, expectation — is a consequence.

<Callout type="info" title="Two readings of the same number">
  What does $P(\text{rain}) = 0.3$ *mean*? The **frequentist** reading: in many repeats of days like this one, 30% are rainy. The **Bayesian** reading: 0.3 is a degree of belief, which new evidence should update. The axioms above don't care which story you tell — both readings obey the same math, and ML uses each where it fits ([Bayesian inference](/courses/probability-statistics/04-bayesian-inference) leans on the second).
</Callout>

## Conditional probability — the comma and the bar

Two notations carry most of probability's meaning:

$$
P(A, B) = \text{both happen} \qquad P(A \mid B) = \text{$A$ happens, given $B$ did}
$$

They're linked by the **product rule**, arguably the most-used identity in ML:

$$
P(A, B) = P(A \mid B)\, P(B)
$$

Conditioning is *zooming in*: $P(A \mid B)$ throws away every world where $B$ didn't happen and renormalizes what's left. When the zoom changes nothing — $P(A \mid B) = P(A)$ — the events are **independent**, and the product rule collapses to $P(A,B) = P(A)P(B)$. (Naive Bayes builds an entire classifier from pretending this collapse holds.)

### Both of them, as areas of one square

<ConditionalAreaViz />

Every quantity above is a region of the same unit square, which is the cheapest way to keep them apart. The width splits by $B$; inside each column the height splits by $A$. Then $P(A,B)$ is an **area**, and each conditional is that area divided by a different denominator — $P(A\mid B)$ by its own column, $P(B\mid A)$ by everything shaded.

The comma is symmetric. The bars are not, and the default preset shows how badly. Base rate $P(B) = 0.01$, sensitivity $P(A\mid B) = 0.99$, false positives $P(A\mid\lnot B) = 0.05$:

$$
P(A) = 0.01(0.99) + 0.99(0.05) = 0.0594
\qquad
P(B\mid A) = \frac{0.0099}{0.0594} = 0.1667
$$

A test that is right 99% of the time when you are ill leaves you **16.7%** likely to be ill when it fires — a factor of 5.9 between the two conditionals. You do not need Bayes' rule to see why: the square is drawn to scale, and the sliver of true positives is simply dwarfed by a false-positive band that starts out 99× wider. Swapping $P(A\mid B)$ for $P(B\mid A)$ is the single most common probability error in applied work, and it is this picture read in the wrong direction.

Drag $P(B)$ up and the two bars converge; press **independent** and the split stops mattering at all — $P(A\mid B) = P(A\mid \lnot B) = P(A)$, and the vertical line no longer changes any height.

## Random variables

A **random variable** $X$ attaches a number to each outcome — the die's face value, a pixel's brightness, tomorrow's temperature. This is the bridge from raw outcomes to arithmetic: once outcomes are numbers, you can average them, weight them, and feed them to models.

- **Discrete** $X$ takes countable values, described by a probability *mass* function: $P(X = k)$
- **Continuous** $X$ takes values in a continuum, described by a probability *density* function, where only *areas* are probabilities: $P(a \le X \le b) = \int_a^b p(x)\,dx$

The next lesson makes this concrete with the four distributions ML reaches for daily.

<Details summary="Deep dive: why a density can exceed 1">
  A common trip-up: a PDF value is **not** a probability. A uniform on $[0, 0.5]$ has density $p(x) = 2$ everywhere on that interval — perfectly legal, because only the *area* must equal 1, and $2 \times 0.5 = 1$. Probabilities come from integrating the density over a range; the value at a single point can be arbitrarily large (and the probability of any *exact* single value is 0). Heights trade off against widths so the total area stays 1 — you can see this live in the distribution visualization in the next lesson.
</Details>

## Expectation: the long-run average

The **expectation** of a random variable is its probability-weighted average:

$$
\mathbb{E}[X] = \sum_k k \, P(X = k) \qquad \text{or} \qquad \mathbb{E}[X] = \int x \, p(x) \, dx
$$

Roll a fair die forever and your average roll converges to $\mathbb{E}[X] = 3.5$ — a value the die never actually shows. Expectation is the center of mass of belief, not a prediction of any single outcome.

**Variance** measures spread around that center: $\mathrm{Var}(X) = \mathbb{E}[(X - \mathbb{E}[X])^2]$.

You can watch the law of large numbers pull a running average onto the expectation in a few lines:

```python
import numpy as np

rng = np.random.default_rng(0)
rolls = rng.integers(1, 7, size=10_000)

running_mean = np.cumsum(rolls) / np.arange(1, rolls.size + 1)
print(running_mean[[9, 99, 999, 9999 - 1]])
# → drifts toward 3.5 as the sample grows: e.g. [3.1, 3.38, 3.46, 3.50]
```

<Callout type="tip" title="Why ML cares so much about 𝔼">
  Almost every training objective is an expectation: the loss you minimize is the *expected* loss over the data distribution, approximated by averaging over your training set. Gradient descent on a mini-batch works precisely because the mini-batch average is an unbiased estimate of that expectation.
</Callout>

## Key takeaways

- Probability assigns numbers to events under three axioms: non-negative, sums to 1, additive over exclusive events
- The product rule $P(A,B) = P(A \mid B)P(B)$ links joint and conditional probability; independence means conditioning changes nothing
- Random variables turn outcomes into numbers; discrete ones have mass functions, continuous ones have densities (areas = probabilities)
- Expectation is the probability-weighted average — the quantity nearly every ML loss function is secretly approximating
